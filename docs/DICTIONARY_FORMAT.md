# Форматы словарей и личного Dictionary

## Yomitan v3 ZIP

Нужны `index.json` с `format: 3`, названием `title` и файлы `term_bank_N.json` в корне архива. Поддерживаются текстовые и structured-content статьи. Адаптер WTY извлекает значения, примеры с переводами, синонимы, этимологию и ссылки. Оригинальная запись сохраняется в `raw`. Особые записи `non-lemma` WTY дают связи форм с начальной формой и частью речи.

У других словарей Yomitan могут быть собственные структуры и схемы склонения; автоматические связи произвольных форм не обещаются. Незнакомое содержимое показывается текстом, исходный объект сохраняется. Стилевые файлы архива не выполняются и не влияют на новый интерфейс.

## JSON подключённого словаря

Готовый пример: `examples/custom-dictionary.json`. Формальная схема: `golyah/schemas/golyah-dictionary.schema.json`. UTF-8, допускается BOM.

В переносимой сборке опубликованные схемы также находятся в отдельной папке `schemas` рядом с EXE.

```json
{
  "schemaVersion": 1,
  "kind": "golyah-dictionary",
  "name": "My dictionary",
  "revision": "1",
  "attribution": "Own examples",
  "entries": [{
    "word": "run",
    "lemma": "run",
    "pos": "v",
    "forms": ["ran", "running"],
    "senses": [{
      "translation": "бежать",
      "examples": [{"en": "I run every morning.", "ru": "Я бегаю каждое утро."}]
    }],
    "synonyms": ["jog"],
    "etymology": "",
    "sources": ["My own dictionary"]
  }]
}
```

В статье обязательно `word`; остальные поля имеют значения по умолчанию. `senses` содержит перевод и связанные с ним примеры. Необязательное `definition_en` у статьи или отдельного значения содержит английское словарное определение. `pos` — свободная строка части речи, `tags` — список пометок, например `["Figurative"]`, `ipa` — транскрипция. Эти поля показываются под словом, когда присутствуют в источнике. `forms` перечисляет исходные формы, по которым находится эта статья. Дополнительные поля: `extra`, `raw`. Начальная форма без `lemma` берётся из `word`. Название источника указывайте в `sources`, ссылки — полными HTTP(S) URL. Корневая `attribution` сохраняется в метаданных импорта; для отображения атрибуции каждой статьи укажите её также в `sources`.

Название `name` служит идентификатором словаря: повторный импорт с тем же названием заменяет данные атомарно. Для двух независимых словарей используйте разные названия. Увеличенный приоритет ставит словарь выше внутри группы точных совпадений/форм.

Произвольный JSON неизвестного формата потребует отдельного адаптера.

## Экспорт личного Dictionary

Корневые поля `schemaVersion: 1`, `kind: "golyah-study"`, `records: [...]`. Полная схема: `golyah/schemas/golyah-study.schema.json`. Используйте экспорт из интерфейса как образец для переноса данных.

Запись включает `term`, `lemma`, `sentence`, `selected_positions` (полуоткрытые интервалы символов `[start,end]`), `selection_preview`, `entries`, `entry_index`, `sense_index`, редактируемые поля перевода и объяснения, `examples`, `synonyms`, `sources`, исходные `explain`/`context`, модель, состояние, назначение и даты. UID при импорте вычисляется снова из слова и предложения.

Начиная с 0.3 запись также содержит `learning_modes` — непустой список уникальных `forward`, `reverse`, `gap`; `anki_note_ids` — ID заметок по варианту; `anki_paused_cards` — журнал карточек, приостановленных приложением; `anki_modes_pending` — ожидающее обновление вариантов. Прежний `anki_note_id` сохраняется для совместимости. Старый экспорт без новых полей получает вариант `forward`. При отправке после импорта заметки ищутся заново по UID и типу, чтобы ID из другой коллекции не изменили посторонние карточки. Макеты конструктора относятся к настройкам приложения и в экспорт слов не входят.

Необязательные `word_audio` и `sentence_audio` сохранены только для совместимости со старыми экспортами. Они могут содержать `filename`, `text`, `source`, `voice`, `rate`, `credit`, `url`. Файлы аудио в JSON не включаются. В версии 1.0.0 озвучка и загрузка аудио в Anki отсутствуют; прежние поля сохраняются при переносе данных.

Состояния: `draft`, `preview`, `pending_anki`, `saved`; назначения: `dictionary`, `anki`. Отсутствие обязательного LLM-результата превращает импортированную сохранённую запись в черновик. Весь файл проверяется до записи в базу; ошибка не оставляет частичный импорт. При совпадении UID запись заменяется данными файла. Сделайте экспорт перед импортом старой резервной копии.
